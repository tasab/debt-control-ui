# План імплементації — Клієнт

Frontend (`client/`) для P2P-платформи. Похідний від `PLATFORM_PLAN.md`.
Контракт API — `SERVER_PLAN.md` §2 (клієнт його **споживає**, не визначає).

Стек лишається: **React 19 + Vite + Tailwind v4 + shadcn/ui + TanStack Query +
React Router + Zod + Recharts**.

---

## 0. Головне правило

**Клієнт не рахує гроші.** Жодних обчислень балансів, відсотків, комісій чи
конвертацій у React. Все приходить з сервера порахованим; клієнт форматує й
відображає. Наявний `lib/engine.js` переїжджає на сервер і тут видаляється.

Єдина «математика» на клієнті — форматування `bigint`-рядка в текст за
`exponent` валюти.

## 2. Як працювати паралельно з сервером

Це і є відповідь на «чи можна запускати паралельно»: **так, через MSW**.

- `client/src/mocks/` — [MSW](https://mswjs.io) з handler-ами, написаними **строго
  за `SERVER_PLAN.md` §2**. Вмикається `VITE_USE_MOCKS=1`.
- Fixtures покривають і щасливі шляхи, і помилки з §2.4 (`INSUFFICIENT_FUNDS`,
  `QUOTE_EXPIRED`, `RATE_STALE`…) — інакше UI помилок пишеться наосліп і потім
  переробляється.
- `lib/api/*` не знає про моки: перемикання на реальний сервер = зміна env.
- **Контракт міняє тільки сервер.** Якщо клієнту чогось бракує — правка
  `SERVER_PLAN.md` §2, потім моки, потім код. Не навпаки.
- Дефолт `npm run dev` — реальний сервер; моки вмикаються явно.

Ризик: моки розходяться з реальністю. Мітигація — після кожної серверної фази
прогнати клієнт із `VITE_USE_MOCKS=0` і звірити (це окремий чекпоінт у §4).

## 3. Гроші в UI

Найчастіше джерело багів на клієнті. Правила:

- З сервера приходить **рядок мінорних одиниць** (`"100500"`). Ніколи не
  `Number()` над ним — тільки `BigInt` або рядкова робота в `lib/money.js`.
- `<Amount value="100500" currency="UAH" />` — єдиний спосіб показати суму.
  Знак, колір (вхід/вихід), групування розрядів, символ валюти — всередині.
- `<AmountInput />` — вводить користувач `1000.50`, компонент віддає `"100050"`.
  Обробити: кома як роздільник, пробіли, вставка з буфера, більше знаків ніж
  `exponent`.
- Ніколи не показувати «приблизно». Якщо треба еквівалент у UAH — це окреме
  поле з сервера, а не множення на клієнті.

## 4. Фази

C* парні до S* із `SERVER_PLAN.md`. Кожна C може стартувати **одночасно** з
відповідною S (на моках) і закривається чекпоінтом інтеграції.

### C0 — Каркас, auth, гаманець

- Прибрати старе: `Entry.jsx`, `engine.js`, `store.js` (localStorage),
  `schema.js`, сторінки трекера. Залишити `components/ui/*`, `format.js`,
  `utils.js`.
- `api/client.js`: куки, авто-`Idempotency-Key` на всі мутації, нормалізація
  помилок у `{code, message, fields}`, редірект на логін при 401.
- `lib/money.js` + `Amount`/`AmountInput` **з юніт-тестами** (vitest) — це
  фундамент, тестується як серверний реєстр.
- Сторінки: Register (вибір `invest`/`borrow` з поясненням, що це можна буде
  розширити), Login, Wallet Overview (баланси по валютах: доступно / заморожено),
  Transaction History (курсорна пагінація, скелетони).
- AppShell з навігацією, що залежить від `capabilities`.

**Готово коли:** реєстрація → логін → видно баланси й історію з реального сервера.

### C1 — Перекази

Форма переказу: пошук отримувача (debounce), сума, валюта, **коментар**.
Крок підтвердження з `GET /fees/preview` — «спишеться 1005, отримувач отримає 1000».
Обробка `INSUFFICIENT_FUNDS` на полі суми. Оптимістичне оновлення з відкатом.
Історія: фільтри (тип, валюта, період, пошук по коментарю), деталі транзакції.

**Готово коли:** переказ проходить, комісія показана **до** підтвердження,
подвійний клік не створює два перекази.

### C2 — Конвертація валют

Екран обміну: from/to, введення з будь-якої сторони, курс BID/SELL з поясненням
який бік застосовано. **Таймер quote** (60с) з прогрес-баром і кнопкою «оновити».
`QUOTE_EXPIRED` → м'який ре-квот, не помилка на весь екран.
Бейдж `isStale` на курсі, якщо провайдер мовчить — це вимога довіри, не косметика.

**Готово коли:** конвертація за зафіксованим quote, протухання обробляється
без втрати введених даних.

### C3 — Бізнес-профіль

Онбординг бізнесу, керування касами (CRUD), стартовий капітал.
Дашборд: активи / зобов'язання / чиста вартість / P&L / вартість капіталу —
**усе з `GET /businesses/me/dashboard`**, клієнт лише малює. Recharts для динаміки.

**Готово коли:** бізнес бачить P&L проти стартового капіталу.

### C4 — Маркетплейс і позики (найбільша)

- **Список заявок**: фільтри (валюта, мін. ставка, строк, грейд), сортування,
  картка з прогресом збору (`fundedBps`), грейдом бізнесу, кількістю інвесторів.
- **Деталь заявки**: профіль бізнесу, ціль, графік, хто вже профінансував.
- **Діалог фінансування**: сума (з валідацією `minTicket` і залишку),
  прев'ю доходу («за 180 днів отримаєте ~X, з них комісія Y»), підтвердження.
  Явно показати, що кошти **заморожуються**, а не списуються.
- **Створення заявки** (бізнес): сума, валюта, ставка, строк, тип погашення,
  `minTicket`, дедлайн. Прев'ю повної вартості («заплатите X зверху»).
- **Мої позики** (бізнес): графік, наступний платіж, кнопка погашення.
- **Мої інвестиції**: активні частки, нарахований %, найближчі надходження.
- Стани заявки/позики — один компонент-бейдж на всю систему, включно з `overdue`.

**Готово коли:** з UI можна пройти цикл заявка → фінансування двома акаунтами →
видача → погашення → закриття.

### C5 — Рейтинг і аналітика

Графік балансу (Recharts, перевикористати каркас старого `History.jsx`):
по днях, у розрізі валют і в UAH. Розбивка гаманці/у позиках/заморожено.
Рейтинг як грейд + пояснення факторів (не голе число) + дисклеймер.
Портфель інвестора: дохідність, розподіл, попередження про концентрацію.
Експорт CSV.

### C6 — Полірування

Порожні стани, скелетони замість спінерів, тости, підтвердження ризикових дій,
мобільна адаптивність, темна тема, доступність (фокус, aria на сумах),
error boundary, сторінка 404.
